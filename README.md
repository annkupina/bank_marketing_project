# Bank Marketing: прогнозування підписання строкового депозиту

## Мета

Передбачити, чи підпише клієнт строковий депозит, на основі даних прямих телефонних маркетингових кампаній португальського банку ([bank-additional-full.csv, Kaggle](https://www.kaggle.com/datasets/sahistapatel96/bankadditionalfullcsv)). Датасет містить 41 176 записів, 20 ознак (дані клієнта, контакт, історія кампаній, макроекономіка) і цільову змінну `y` з часткою позитивного класу лише 11.3%.

## Моделі

Logistic Regression, kNN, Decision Tree, XGBoost, LightGBM і soft Voting ансамбль. Моделі порівнювались за **ROC-AUC** і **PR-AUC**: через дисбаланс класів accuracy тут неінформативна.

## Підхід

### Feature engineering

- Видалено `duration`: тривалість дзвінка відома лише після його завершення, тобто це витік цільової змінної.
- `pdays = 999` замінено на `-1` (ознака `days_since_last_contact`), додано `had_previous_contact` і `age_group`.
- Через сильну кореляцію між макроознаками (до 0.98) прибрано `emp.var.rate`, `euribor3m` і `cons.conf.idx`.
- Застосовано OneHot-кодування категорій і `StandardScaler` для лінійної моделі та kNN.

### Пайплайн

Препроцесинг і модель об'єднано в один scikit-learn `Pipeline`. Дані хронологічні, тому розбиття часове: 80% train / 20% test. Гіперпараметри підбирались через `RandomizedSearchCV` з `TimeSeriesSplit` і через Hyperopt (TPE).

### Дисбаланс класів

Для дисбалансу використано `class_weight='balanced'`, `scale_pos_weight ≈ 14.7` для бустингів і `RandomUnderSampler` для kNN. Undersampling приросту не дав.

### Важливість ознак

Аналізувались коефіцієнти логістичної регресії і SHAP. Найважливіші ознаки: місяць (індикатор економічного періоду), `poutcome = success` і вік 65+.

### Аналіз помилок

При порозі 0.8 f1-score становить 0.57 для класу «так» і 0.77 для класу «ні». Найвпевненіше модель помиляється на комбінаціях `poutcome` + `nr.employed`.

## Результати

| Модель | ROC-AUC train | ROC-AUC test | PR-AUC test |
|---|:---:|:---:|:---:|
| **Logistic Regression** ✅ | 0.686 | 0.748 | 0.519 |
| kNN (k=5) | 0.924 | 0.638 | 0.418 |
| kNN (k=150) | 0.709 | 0.715 | 0.512 |
| kNN (undersampling) | 0.726 | 0.657 | 0.415 |
| Decision Tree (base) | 1.000 | 0.534 | 0.327 |
| Decision Tree (max_depth=10) | 0.738 | 0.672 | 0.445 |
| XGBoost (base) | 0.917 | 0.620 | 0.423 |
| XGBoost (RandomizedSearchCV) | 0.714 | 0.743 | 0.536 |
| XGBoost (Hyperopt) | 0.709 | 0.735 | 0.506 |
| LightGBM (RandomizedSearchCV) | 0.994 | 0.658 | 0.433 |
| LightGBM (Hyperopt) | 0.767 | 0.744 | 0.571 |
| Voting (LogReg + XGB + kNN) | 0.698 | 0.749 | 0.531 |

## Висновки

Фінальна модель — **Logistic Regression**: не поступається бустингу і ансамблю, не перенавчена і повністю інтерпретована. Базові дерева, kNN і бустинги сильно перенавчаються. Головна складність даних — зсув у часі: частка підписань у train становить 6.4%, а в test — 30.8%.

## Що можна покращити

Замінити `month` на явні ознаки періоду. Додати взаємодії ознак.
